Eres un desarrollador senior Python/Flask. Trabajas en un proyecto universitario llamado
"Growth Horizon": una plataforma web multi-empresa que diagnostica el nivel de madurez
empresarial y digital de negocios de cualquier tamaño (desde una tienda de barrio hasta una
empresa grande).

CONTEXTO: El proyecto actual está armado como un sistema de administración de ventas de un solo
negocio (con módulos de ventas, inventario y horarios). Necesito corregirlo para que sea una
plataforma de diagnóstico multi-empresa.

**ALCANCE DEL PROYECTO — LEE ESTO ANTES DE EMPEZAR:**
Esta plataforma NO es un sistema de gestión de ventas, inventario u operación diaria del
negocio del cliente. Es una herramienta de EVALUACIÓN/DIAGNÓSTICO: la empresa responde un
cuestionario organizado por dimensiones, el sistema calcula un índice de madurez ponderado, lo
compara contra el promedio de su sector, lo segmenta (Inicial / En Desarrollo / Consolidado) y
le da recomendaciones. El flujo central es: RESPONDER → CALCULAR → COMPARAR → RECOMENDAR.
Cualquier funcionalidad que sirva para que el cliente opere su negocio (vender, gestionar
stock, llevar horarios de atención) está FUERA de alcance, sin importar qué tan útil parezca.
Los datos operativos relevantes (ingresos, control de inventario, canal de venta, etc.) se
capturan como preguntas dentro del mismo cuestionario de diagnóstico — nunca como módulos CRUD
independientes.

=== CAMBIO 4: AGREGAR MODELOS DE DIAGNÓSTICO ===
Crear los siguientes modelos en models/ (mismo estilo ORM que los existentes):

1. models/dimension.py:
   - id (Integer, PK)
   - nombre (String(100), unique, not null)
   - descripcion (Text, nullable)
   - peso (Numeric(5,2), default=1.0) — para el promedio ponderado

2. models/indicador.py:
   - id (Integer, PK)
   - dimension_id (Integer, FK → dimensiones.id, not null)
   - texto (Text, not null) — texto de la pregunta
   - peso (Numeric(5,2), default=1.0)
   - tipo_medicion (String(20), not null, check in ('AUTOREPORTADO', 'CALCULADO'))
   - Relación: dimension = db.relationship(...)

3. models/respuesta_diagnostico.py:
   - id (Integer, PK)
   - empresa_id (Integer, FK → empresas.id, ON DELETE CASCADE, not null)
   - indicador_id (Integer, FK → indicadores.id, not null)
   - valor (Numeric(5,2), not null) — puntaje 0-100
   - fecha (DateTime, default=datetime.utcnow)
   - UniqueConstraint(empresa_id, indicador_id)
   - Relaciones: empresa, indicador

4. models/indice_madurez.py:
   - id (Integer, PK)
   - empresa_id (Integer, FK → empresas.id, ON DELETE CASCADE, not null)
   - dimension_id (Integer, FK → dimensiones.id, not null)
   - puntaje (Numeric(5,2), not null)
   - fecha (DateTime, default=datetime.utcnow)
   - Relaciones: empresa, dimension
   - Esta tabla es la fuente de la trazabilidad histórica del diagnóstico (cada recálculo deja
     un snapshot con fecha) — no se necesita ninguna tabla operativa adicional para tener
     historial.

5. models/segmento.py:
   - id (Integer, PK)
   - nombre (String(50), unique, not null) — "Inicial", "En Desarrollo", "Consolidado"
   - rango_min (Numeric(5,2), not null)
   - rango_max (Numeric(5,2), not null)
   - descripcion (Text, nullable)

6. models/recomendacion.py:
   - id (Integer, PK)
   - dimension_id (Integer, FK → dimensiones.id, not null)
   - rango_min (Numeric(5,2), not null)
   - rango_max (Numeric(5,2), not null)
   - texto (Text, not null)
   - prioridad (String(20), not null, default='MEDIA', check in ('BAJA', 'MEDIA', 'ALTA'))
   - Relación: dimension
